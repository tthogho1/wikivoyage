**分けた方が効果がある可能性が高いです。** ただし「完全に別々」ではなく、**テキスト検索は専用埋め込みモデル、画像検索はSigLIP 2**に分け、必要なら両方の結果を統合する構成が最も実用的です。

## なぜ分けるか

SigLIP 2は画像とテキストを同じ空間に置くため、**テキスト→画像**検索には優れています。しかし、WikiVoyageの長文・地名・交通手段・宿泊・歴史・専門用語のようなテキスト検索では、SigLIP 2のテキストエンコーダは汎用テキスト検索向けに最適化されていません。

SigLIP 2は画像・テキストの共通埋め込みを生成するビジョン言語エンコーダで、クロスモーダル検索やオブジェクト検索向けです。 一方、専用テキスト埋め込みモデルは、長文の意味検索、複雑な質問、専門用語、類似文の区別に強い設計です。

| 検索対象 | 推奨モデル | 理由 |
|---|---|---|
| テキストチャンク | 専用テキスト埋め込みモデル | 長文・専門用語・複雑な質問に強い |
| 画像チャンク | SigLIP 2 | 画像と英語クエリを同一空間で比較できる |
| 英語クエリ → テキスト | 専用テキスト埋め込みモデル | テキスト検索精度を最大化 |
| 英語クエリ → 画像 | SigLIP 2 | テキストと画像を直接比較できる |
| 画像クエリ → 画像 | SigLIP 2 | 画像同士の類似検索に最適 |

## 推奨構成

WikiVoyageのRAGなら、次の**ハイブリッド構成**が最も効果的です。

```text
テキストチャンク → 専用テキスト埋め込み → text_embedding
画像チャンク     → SigLIP 2画像エンコーダ → image_embedding
英語クエリ      → 専用テキスト埋め込み → text_embedding検索
英語クエリ      → SigLIP 2テキストエンコーダ → image_embedding検索
画像クエリ      → SigLIP 2画像エンコーダ → image_embedding検索
```

つまり、**テキスト検索と画像検索は別々のインデックス**にし、検索時に両方を呼びます。これが最も精度が出やすい構成です。

## なぜ統一しない方がよいか

SigLIP 2に統一すると、実装は簡単ですが、次の問題が出ます。

- **テキスト検索の精度が落ちる可能性**：長文・専門用語・複雑な質問では、専用テキスト埋め込みモデルの方が強い
- **画像検索とテキスト検索の精度トレードオフ**：SigLIP 2は画像検索に最適化され、テキスト検索は副次的
- **WikiVoyageのような長文ドキュメントには不向き**：SigLIP 2は画像中心の検索に設計され、長文の意味検索には弱い

SigLIP 2はマルチモーダル検索には強い一方、長文ドキュメント検索には、専用テキスト埋め込みモデルの方が適しています。 Jina Embeddings v4のような統合型マルチモーダル埋め込みモデルもありますが、これは3.8Bパラメータで、ローカル実行にはやや重いです。

## 画像検索との共存

画像検索はSigLIP 2、テキスト検索は専用モデル、という分離は問題ありません。Zilliz Cloudでは、次のようにフィールドを分けます。

```text
chunks[embedding]        → 専用テキスト埋め込みモデル
chunks[image_embedding]  → SigLIP 2画像エンコーダ
```

検索時は、英語クエリを両方のモデルで埋め込み、それぞれのインデックスを検索します。

```text
query → 専用テキスト埋め込み → chunks[embedding] 検索
query → SigLIP 2 text encoder → chunks[image_embedding] 検索
→ 両結果を統合して上位を返す
```

## 実務的な判断

| 状況 | 推奨 |
|---|---|
| テキスト検索精度を最優先 | **分ける**（専用テキスト埋め込み＋SigLIP 2） |
| 実装を最も簡単にしたい | SigLIP 2に統一 |
| 画像検索が主目的 | SigLIP 2中心、テキスト検索は補助 |
| テキスト検索も重要 | **分ける** |
| ローカルで軽くしたい | SigLIP 2に統一、または軽量テキスト埋め込みを併用 |

## 具体的な推奨

あなたのケース（WikiVoyageのRAG、テキストと画像の両方を検索、画像も画像で検索）なら、次が最適です。

- **テキストチャンク**：専用テキスト埋め込みモデル（例：`jina-embeddings-v3`、`bge-m3`、`nomic-embed-text`）
- **画像チャンク**：SigLIP 2画像エンコーダ
- **英語クエリ → テキスト**：専用テキスト埋め込みモデル
- **英語クエリ → 画像**：SigLIP 2テキストエンコーダ
- **画像クエリ → 画像**：SigLIP 2画像エンコーダ
- **回答生成**：Qwen2.5-VL

この構成なら、**テキスト検索の精度を最大化しつつ、画像検索もSigLIP 2で高精度に保てます**。SigLIP 2に統一するのは、実装の簡潔さを優先する場合だけにしてください。

## 補足：統合型の選択肢

どうしても1モデルで統一したいなら、**Jina Embeddings v4**が候補です。テキストと画像を同一アーキテクチャで処理し、単一ベクトルと遅延相互作用型の複数ベクトルの両方をサポートします。 ただし3.8Bパラメータで、ローカル実行にはある程度のGPUメモリが必要です。

つまり、**「テキスト検索の精度を大幅に上げたい」なら分ける方が効果的**です。SigLIP 2に統一するのは、画像検索中心で、テキスト検索は補助的な場合に限られます。
